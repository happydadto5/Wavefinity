## Problem

Edge Mount is currently shown as a permanent top-level ordinary-bin option. That is the wrong user model. It should be selected from the same Parts palette as Divider, Bore, Nest, Post, Pocket, Slot, etc.

The backend architecture is already correct: Edge Mount is a box-level modifier stored as `BoxSpec.edge_mount` / `box.edge_mount`, with geometry in `organizer_edge_mount.py`. It is **not** an interior `Feature`, has no 2D zone, and must not be migrated into `Layout.features[]`.

Implement a UI/workflow demotion only: make Edge Mount look and behave like a Part to the user while retaining the existing box-level data/geometry model.

## Required behavior

- Ordinary Bin Parts palette includes **Edge Mount**.
- Only one Edge Mount may exist per bin.
- It may coexist with ordinary interior parts.
- Clicking its palette tile opens the normal Part editing area, but merely opening it does not modify the design.
- Projecting Label and Screw Mounting remain options inside one Edge Mount.
- Mounting side remains Front / Back / Left / Right.
- Edge Mount is not draggable/resizable in 2D and never gets a fake zone.
- Save Part commits it; Delete Part removes/resets it.
- Active Edge Mount appears in Placed Parts and can be reopened there.
- Existing designs with `box.edge_mount` load unchanged and appear as already having Edge Mount placed.
- Edge Mount remains unavailable for B4B and Base Trim.
- No design schema bump or migration.

## Architecture boundary

Do **not** move Edge Mount into or register it with:

- `organizer_inserts`
- `Feature`

- `FEATURE_BUILDERS`
- `Layout.features`
- `/api/feature/default`

Keep `organizer_edge_mount.py`, `EdgeMountSpec`, `BoxSpec.edge_mount`, and existing serialization/geometry behavior intact unless current main reveals a concrete bug unrelated to this UI move.

### 4. `web/app.js` — add a contained virtual-part state boundary

Add one explicit state flag, e.g.:

```javascript
edgeMountEditing: false,
```

Add helpers:

```javascript
function editingEdgeMount() {
  return state.edgeMountEditing === true;
}

function edgeMountActive(design = state.design) {
  const one = design?.box?.edge_mount;
  return Boolean(one?.label_enabled || one?.holes_enabled);
}

function placedPartCount() {
  return (state.design?.layout?.features?.length || 0)
    + (edgeMountActive(state.design) ? 1 : 0);
}
```

Keep the special case contained around palette selection, editor presentation, save/delete, and Placed Parts rendering. Do not spread `kind === "edge_mount"` checks through unrelated layout code.

### 5. Palette selection

In `pickKind(kind)`, branch before `selectKind(kind)`:

```javascript

  selectEdgeMount();
  return;
}
```

Implement `selectEdgeMount()`.

It should:

1. Run the existing draft-switch guard if an interior part is open.
2. Cancel pending interior draft work.
3. Clear the ordinary layout selection without deleting anything.
4. Set `state.edgeMountEditing = true`.
5. Open `.support-editor`.
6. Highlight the Edge Mount palette tile.
7. Hide `#draft-fields`.
8. Show `#edge-mount-editor`.
9. Set editor title/description from the Edge Mount catalog entry.
10. Run the existing Edge Mount choice population/sync functions.
11. Show the normal Save Part / Delete Part actions.

Do not call `/api/feature/default` for Edge Mount.

Do not create a fake `state.draft` Feature merely to satisfy existing code.

When any real interior part is selected/reopened, clear `edgeMountEditing`, show `#draft-fields`, and hide `#edge-mount-editor`.

Update `clearDraftSelection()` so it also exits Edge Mount editing cleanly.

### 6. Stop hidden Edge Mount controls from mutating every design

Current `updateDesignFromForm()` calls `readEdgeMountForm(design)` unconditionally.

Change that to only read Edge Mount controls while Edge Mount is being edited:

```javascript
if (editingEdgeMount()) {
  readEdgeMountForm(design);
}
```

Similarly, do not let routine `syncForm()` overwrite the hidden Edge Mount editor during unrelated edits. `populateEdgeMountChoices()` may remain initialization-safe, but only run `syncEdgeMountControls()` when Edge Mount is the active editor.

The existing saved `state.design.box.edge_mount` remains the truth when the editor is closed.

### 7. Live editing semantics

Defaults have both subsections off, so the inactive editor is only a draft UI state.

Once the user enables Projecting Label or Screw Mounting, the existing design-change/preview path may update live.

Do not consider Edge Mount placed until `edgeMountActive()` is true.

Do not duplicate Python geometry-fit validation in JavaScript.

### 8. Save Part

At the top of `saveCurrentPart()`, branch:

```javascript

  return saveEdgeMountPart();
}
```

Implement `saveEdgeMountPart()` as a box-level design save, not an interior-feature apply.

Required flow:

- if both Projecting Label and Screw Mounting are off, keep the editor open and tell the user to enable at least one option;
- clone the prior design;

- show the normal saved feedback.

Do not call `/api/feature/apply`.

- clone previous design;
- remove/reset `state.design.box.edge_mount` to inactive;
- canonicalize if needed through the existing design validation/serialization path;
- record history;
- return to the palette;
- refresh Placed Parts and preview.

Deleting a brand-new inactive Edge Mount editor simply closes/discards it.

Do not add an Edge Mount-specific backend delete route unless current main proves one is actually required.
