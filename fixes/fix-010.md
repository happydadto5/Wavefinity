# Part A — Compact Interior Parts / Parts & options cards

## User requirement

The feature-choice cards under **Parts & options** should be about **30% shorter** so more choices fit vertically.

Do **not** make the feature icon artwork smaller. Instead, crop/zoom the artwork so the actual icon uses more of its available square.

## Current implementation

`web/styles.css` currently defines:

- `.support-choice` at 48 px min/max height.
- `.support-choice-icon` at 48 px wide.
- `.support-choice-icon svg` at 34 × 34 px.

`web/app.js::iconFor(kind)` currently renders every feature icon with:

```js
const common = 'viewBox="0 0 32 32" aria-hidden="true"';
```

The SVG path artwork itself has substantial internal whitespace, so the visible glyph is smaller than the nominal 34 px SVG box.

## Required CSS change

In `web/styles.css`:

### 1. Reduce normal palette-card height from 48 px to 34 px

34 px is the target because it is approximately 30% below 48 px.

Change the normal `.support-choice` card to:

```css
.support-choice {
  --support-color: var(--teal);
  min-height: 34px;
  max-height: 34px;
  padding: 0;
  background: white;
  border: 1px solid var(--line);
  border-radius: 8px;
  cursor: pointer;
  text-align: left;
  display: flex;
  align-items: stretch;
  gap: 0;
  overflow: hidden;
}
```

Equivalent formatting is fine, but the effective normal-card height should remain 34 px.

### 2. Keep the SVG itself 34 × 34 px

Do **not** reduce the existing:

```css
.support-choice-icon svg {
  width: 34px;
  height: 34px;
}
```

### 3. Make the icon tile match the compact row without shrinking the SVG

Change `.support-choice-icon` from a 48 px column to a 34 px column:

```css
.support-choice-icon {
  display: grid;
  place-items: center;
  flex: 0 0 34px;
  width: 34px;
  align-self: stretch;
  overflow: hidden;
  border-radius: 7px 0 0 7px;
  color: var(--support-color);
  background: color-mix(in srgb, var(--support-color) 14%, white);
}
```

The SVG remains 34 × 34, so the rendered SVG is **not** made smaller.

### 4. Tighten the text so the shorter card stays readable

Keep the title at its current readable size. Compress only spacing/description height. Recommended exact values:

```css
.support-choice-copy {
  flex: 1;
  min-width: 0;
  padding: 2px 6px;
  display: flex;
  flex-direction: column;

  line-height: 1.1;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
  display: block;

```

Do not reduce the title font size.

### 5. Preserve editing mode

The existing `.support-palette.editing .support-choice.active` intentionally expands to a larger editing chip. Do **not** force that active editing card to 34 px. Its current expanded editing behavior may remain.

## Required icon zoom

In `web/app.js::iconFor(kind)`, tighten the common feature-icon viewBox from 32 × 32 to a safe 28 × 28 crop:

```js
function iconFor(kind) {
  const common = 'viewBox="2 2 28 28" aria-hidden="true"';
  const iconId = partInfo(kind)?.icon || kind;
  const paths = window.WavefinityFeatureIcons || {};
  return `<svg ${common}>${paths[iconId] || paths.pocket || ""}</svg>`;
}
```

The current feature paths in `web/feature-icons.js` remain inside that crop. Do not rewrite the individual icon artwork unless implementation reveals a real clipping defect.

This satisfies the user's intent: same nominal 34 px SVG, shorter 34 px card, and visibly larger artwork inside the SVG.

# Part C — Route New Space through the three-image type chooser

## Current bug

`web/spaces.js::SP.newDrawerSpace()` currently does this:

```js
SP.clearSetupContext();
SP.showSetup("drawer", state.activeSpace);
document.getElementById("space-name").value = "";
```

That bypasses the existing **Drawer / Surface / Portable Storage** image chooser and therefore assumes every new Space is another Drawer.

## Required behavior

Pressing **New Space** from any active typed Space must:

1. keep the current Space unchanged;
2. clear stale create/configure/collision state;
3. remember a **read-only copy** of the current Space only as a potential same-type dimension template;
4. show the existing `#space-type-cards` screen with the three existing images;
5. let the user choose Drawer, Surface, or Portable Storage;
6. if the chosen type matches the current Space type, prefill its physical dimensions from the current Space;
7. if the chosen type differs, start that type with blank/default dimensions as the ordinary new-type flow already does;
8. always start the new Space **name blank**;
9. continue through the existing folder-last `SP.create()` path.

The same-type carry-forward rule applies consistently:

- Drawer → Drawer: carry width/depth/usable height.
- Surface → Surface: carry width/depth and the current trim size.
- Portable → Portable: carry width/depth/usable height.
- Any cross-type choice: do not inherit dimensions.

A legacy `box` current kind is treated as `portable`, matching the rest of the current migration UI.

## Recommended implementation — reuse the existing prefill pipeline

Do **not** build a second chooser or a second form path.

The current type-card click handler already uses `SP.setupPrefillSpace` and only gives that candidate to the matching type. Reuse that mechanism.

### 1. Broaden the comment on `SP.setupPrefillSpace`

At the top of `web/spaces.js`, change the comment from inventory-only wording to something like:

```js
// A read-only setup candidate offered only to its matching type card.
// It may come from existing inventory/layout recovery or from an explicit
// New Space repeat-size template. It is never itself the active Space.
setupPrefillSpace: null,
```

No new persistent Space-state object is needed.

### 2. Replace `SP.newDrawerSpace()` with `SP.newSpace()`

Use this implementation shape:

```js
SP.newSpace = () => {
    if (!state.activeSpace) return;

    const template = clone(state.activeSpace);
    if (template.kind === "box") template.kind = "portable";
    template.name = "";

    // Clear stale folder/collision/edit state first, then install only the
    // read-only repeat-size template for the type chooser.
    SP.clearSetupContext();
    SP.setupPrefillSpace = template;
    SP.showTypeCards();
};
```

Do not call `SP.showSetup("drawer", ...)` from this action.

### 3. Keep the existing type-card matching rule

The current handler already does:

```js
const kind = el.dataset.kind;
const candidate = SP.setupPrefillSpace;
const candidateKind =
  candidate?.kind === "box" ? "portable" : candidate?.kind;
SP.showSetup(kind, candidateKind === kind ? candidate : null);
```

Preserve that behavior.

Because the New Space template has `name = ""`, a same-type selection receives the old dimensions but never the old name.

Do not make a cross-type selection inherit dimensions.

### 4. Rename the event wiring

In `wireInfoButtons(prefix = "space-info")`:

- change the button suffix from `-new-drawer` to `-new-space`;
- bind it to `SP.newSpace`.

Target shape:

```js
const btnNew = document.getElementById(prefix + "-new-space");
if (btnNew) btnNew.addEventListener("click", SP.newSpace);
```

Update comments to say **New Space** rather than **New Drawer Space**.

### 5. Show New Space for every active typed Space

`SP.renderSpaceInfo()` currently hides the button unless `kind === "drawer"`.

Change the lookup to `prefix + "-new-space"` and make the button visible for any active typed Space. The surrounding Space Info block is already hidden when the folder is not a typed Space, so no extra Design-mode exposure is needed.

Target:

```js
const btnNew = document.getElementById(prefix + "-new-space");
if (btnNew) btnNew.hidden = false;
```

This makes **New Space** available from Drawer, Surface, and Portable Space Info.
