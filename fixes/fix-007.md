# Product contract

## A. Existing side connectors remain the normal two-bin connector

The existing Side connector remains the default connector type.

Its fit must continue to come automatically from the active bin's actual wall thickness. There is no separate user-editable connector wall-thickness field.

Current code already does the important geometry correctly:
- BoxSpec.wall is the active bin wall thickness.
- BoxSpec.wall_depth derives the true normal-depth requirement.
- connector_half_widths(box, connector) uses box.wall_depth.
- make_side_connector() uses those half-widths.
- connector_filename(..., wall=box.wall) already identifies non-standard wall thicknesses.

Do not create a second thickness system. Preserve that path and make the automatic behavior clear in the UI.

Side connectors continue to support the existing Same / Different bin-height behavior. Do not remove or weaken different-height side connectors.

## B. Add a 3-Way Corner connector

A 3-Way Corner connector joins three equal-height, equal-wall-thickness ordinary Wavefinity bins whose corners meet at one grid junction, with the fourth quadrant empty.

The canonical generated shape uses the northwest, northeast, and southwest quadrants, leaving the southeast quadrant empty. The physical part is universal: the user rotates it on the bins to put the empty quadrant wherever needed. Do not add a separate orientation selector.

It is a small top/rim connector. It does not run down the full height of the bins except for the same short connector-arm depth already used by a normal side connector.

It does NOT support different bin heights.

## C. Add a 4-Way Corner connector

A 4-Way Corner connector joins four equal-height, equal-wall-thickness ordinary Wavefinity bins meeting at one grid junction, one bin in each quadrant.

It is also a small top/rim connector using the existing connector cap/arm depth.

It does NOT support different bin heights.

## D. Corner connectors require equal wall thickness

All participating bins for a 3-Way or 4-Way connector must use the same wall thickness.

Wavefinity does not attempt to generate a transition connector between different wall thicknesses.

A Space is still allowed to contain mixed wall thicknesses. Same-thickness bins inside that Space may still use connectors with each other.

## E. Exact mixed-wall warning rule

The user clarified this requirement specifically:

**Warn when the user changes the Wall thickness control while working in a typed Space and that Space already contains at least one ordinary inventory bin with a known wall thickness different from the newly resolved wall thickness.**

This is a warning, not a block.

Use wording substantially like:

"This Space already has bins with a different wall thickness. Connectors only fit bins with the same wall thickness. You can keep this thickness, but do not use one connector across different wall thicknesses."

Rules:
- Trigger only from a user-initiated change of the wall-thickness control.
- Do not show the warning merely because a Space with mixed walls is opened.
- Do not show it during initial page load/form synchronization.
- Do not show it for automatic wall promotion caused internally by another feature.
- Compare against ordinary inventory rows only: kind == "bin".
- Ignore B4B rows and spacer rows because they do not use this connector system.
- Ignore legacy inventory rows whose wall is missing, null, non-numeric, or non-positive. Never guess their wall thickness.
- If every known ordinary-bin wall matches the new wall, do not warn.
- If there are no ordinary bins with a known wall, do not warn.
- Editing an existing design is not exempt: if its changed wall differs from existing ordinary bins in the Space, warn.
- Keep the selected wall value after the warning; do not revert it and do not require confirmation.

The comparison must use the final wall value Wavefinity resolved after its normal wall rules, not a stale previous value.

# Implementation

## 1. organizer_engine.py — build corner geometry from the proven side connector

Do not create a second wall-fitting algorithm and do not copy the side connector's corridor/notch math.

### 1.1 Update the module description

Replace the statement that there is only one connector / no corner connector with a short description that the side connector is the primitive and 3-way/4-way corner connectors compose that same fitted side geometry around a grid junction.

### 1.2 Add only the small corner constants needed

Add these near the existing connector constants:

- CORNER_CONNECTOR_MID_GAP = 0.5
  - total longitudinal gap left between two corner connectors that face each other from opposite ends of the minimum 8 mm wall;
- CORNER_CONNECTOR_LEG_START = CORNER_INSET
  - current value: 1.0 mm from the junction;
- CORNER_CONNECTOR_LEG_END = GRID_PITCH / 2.0 - CORNER_CONNECTOR_MID_GAP / 2.0
  - current value: 3.75 mm from the junction.

Do not create new tolerance, wall-width, arm-depth, lock, or wave constants for corner connectors.

Why these exact numbers matter:
- the wall itself stops CORNER_INSET = 1 mm short of the nominal grid corner, so a corner leg should not pretend there is wall from 0..1 mm;
- on the minimum 8 mm wall, the connector from one corner occupies 1.0..3.75 mm;
- a connector approaching from the opposite corner occupies 4.25..7.0 mm;
- the two parts therefore leave 0.5 mm between them instead of colliding or overlapping;
- longer Wavefinity walls simply have more unused wall between the compact corner clips;
- no corner leg reaches the normal lock-bump region deliberately. The corner part is stabilized by two/four perpendicular tight-fit wall channels, not by pretending the side connector's lock bumps exist close to a corner.

### 1.3 Extract the existing wall-following corridor polygon helper

The corner connector must use the exact same wall-thickness and wave-fitting math as the side connector without copying that math.

Inside the existing connector section of organizer_engine.py, extract the nested corridor polygon logic from make_side_connector() into a private module helper conceptually equivalent to:

_connector_corridor_polygon(axis, geometry_coordinates, phase_offset, half_width)

Required behavior:
- axis is "x" or "y";
- geometry_coordinates are the actual coordinates where the returned polygon is drawn;
- phase_offset is added only when evaluating wave_value(), so the mature side connector can keep a locally centered mesh while reading the wave at its requested phase;
- half_width is inner_hw or outer_hw;
- preserve the exact near/far ordering and validity check currently used by make_side_connector().

Then change make_side_connector() to call that helper for its body corridor and channel corridor.

This refactor must be mechanical. Do not change the side connector's samples, phase, dimensions, notches, extensions, web, or returned coordinate system.

For the normal side connector:
- geometry coordinates remain local -length/2 .. +length/2;
- phase_offset remains position.

For corner legs:
- geometry coordinates are already junction-relative global coordinates;
- phase_offset is 0.

This is safe because every Wavefinity grid junction is on the same 4 mm wave phase: legal bin dimensions are multiples of 8 mm, and 8 mm is two full WAVE_LENGTH cycles.

### 1.4 Extract the existing arm/base clearance check

The mature side connector already rejects a connector whose hanging arms would run into the base or flat-inside band on a shallow bin.

Move only that existing band_top / arm_bottom validation loop into a private helper such as:

_validate_connector_arm_clearance(box, connector, heights)

Then:
- call it from make_side_connector() at the exact same point with its existing two resolved heights;
- call it from make_corner_connector() with the one equal height box.z.

Do not alter the messages or thresholds for the side path unless wording must become connector-generic.

This prevents a new corner connector from bypassing an existing physical safety check.

### 1.5 Add a compact friction-grip corner leg

Add a private helper conceptually equivalent to:

_corner_connector_leg(box, connector, axis, direction)

Rules:
- axis must be "x" or "y";
- direction must be +1 or -1;
- compute inner_hw, outer_hw = connector_half_widths(box, connector);
- for direction +1, use geometry coordinates from CORNER_CONNECTOR_LEG_START through CORNER_CONNECTOR_LEG_END;
- for direction -1, use the mirrored range -CORNER_CONNECTOR_LEG_END through -CORNER_CONNECTOR_LEG_START;
- sample that range at the existing SAMPLES_PER_MM density;
- build the outer body with _connector_corridor_polygon(..., phase_offset=0, half_width=outer_hw) and extrude to connector.height;
- build the channel using the same corridor helper with inner_hw and with its longitudinal sample range extended by the same 0.5 mm end overtravel the side connector currently uses, so the channel is open at both leg ends;
- extrude the channel only to connector.arm_depth;
- subtract channel from body;
- return the normal cleaned result.

Important: do NOT cut side-lock notches into this short corner leg.

That is intentional, not an omission:
- ordinary wall lock bumps are kept LOCK_CORNER_CLEAR away from physical corners;
- a minimum 8 mm side has no normal lock bump available there at all;
- extending a corner leg far enough to chase a lock bump makes opposite corner clips collide on small bins;
- the 3-way/4-way part instead gets its stability from multiple perpendicular channels using the same tight tolerance and same wall-following profile as the proven side connector.

Do not loosen connector tolerance for the corner type.

### 1.6 Add make_corner_connector(box, connector, ways)

Public signature:

make_corner_connector(box: BoxSpec, connector: ConnectorSpec, ways: int) -> trimesh.Trimesh

Behavior:
- accept only ways == 3 or ways == 4; otherwise ValueError;
- never accept bin_a_height, bin_b_height, different_heights, web thickness, or auto-adjust inputs;
- call _validate_connector_arm_clearance(box, connector, (box.z,)) before geometry construction;
- compute inner_hw, outer_hw = connector_half_widths(box, connector) for the shared wall fit and central cap size;
Do not add a separate solid center hub. The short perpendicular connector bodies already overlap in their cap layer inside each occupied quadrant, which makes the result one connected printed part. A separate square hub would unnecessarily spread toward neighboring junctions on very small/thick-wall bins.

For ways == 3, use exactly:
- north leg: axis "y", direction +1;
- west leg: axis "x", direction -1.

Their solid cap layers overlap in the northwest occupied quadrant. That overlap joins the two legs into one physical part. The shape joins NW + NE through the north wall channel and NW + SW through the west wall channel, thereby joining the three occupied quadrants. The user rotates the printed part for a different empty quadrant.

For ways == 4, use exactly:
- north leg: y, +1;
- south leg: y, -1;
- east leg: x, +1;
- west leg: x, -1.

Each adjacent pair overlaps in its occupied quadrant at the cap layer, producing one connected cross-corner part without filling the nominal center void.

Union the legs and return the normal cleaned/manifold result using the same cleanup helper already used by connector geometry. Do not merely concatenate overlapping solids.

This design deliberately shares:
- connector_half_widths();
- the exact extracted wave corridor helper;
- ConnectorSpec tolerance, cap thickness, height, and arm depth;
- the same cap-down print orientation later in organizer_app.py.

It deliberately does not share the side connector's lock-notch or different-height web machinery because those mechanisms do not physically apply at a compact corner junction.

### 1.5 Do not alter existing side behavior

No intended output change to make_side_connector(), connector_half_widths(), lock geometry, different-height web logic, or ordinary side filenames is part of this fix.

The two explicitly required mechanical extractions above (corridor polygon + arm/base clearance validation) are allowed only so corner geometry reuses existing physical rules. The pre-existing side connector output for the same inputs must remain behaviorally unchanged.

# Exact edge cases

1. Standard 0.8 mm wall + Side:
   existing side geometry and filename behavior stay normal.

2. Custom 1.6 mm wall + Side:
   connector channel uses the 1.6 mm BoxSpec wall automatically and filename includes Wall 1.6mm.

3. Custom 1.6 mm wall + 3-Way:
   all legs use the same 1.6 mm wall-derived connector_half_widths; filename identifies 1.6 mm.

4. Custom 2.4 mm wall + 4-Way quantity 4:
   produce one 3MF containing four separated 4-way connector copies; filename identifies quantity and wall.

5. Corner type + Different heights submitted by a stale/malicious client:
   backend rejects even if frontend would normally hide/force Same.

6. Minimum 8 x 8 mm bins:
   corner connector is still legal because each leg occupies only 1.0..3.75 mm or -3.75..-1.0 mm from its junction. A corner connector from the opposite end starts at 4.25 mm, leaving a 0.5 mm longitudinal gap. Do not apply the ordinary full-side-connector minimum-length rule to this compact corner geometry.

7. Mixed Space inventory [0.8, 1.2], user changes current Wall to 1.2:
   warn because a known 0.8 bin differs.

8. Space inventory [1.2, 1.2], user changes current Wall to 1.2:
   no warning.

9. Space inventory has old rows with wall missing:
   ignore unknown rows; do not guess 0.8.

10. Space inventory contains only B4B 1.2 plus ordinary bins 0.8, user chooses 0.8:
    no warning due to B4B; compare kind == "bin" only.

11. User opens an already-mixed Space without touching Wall:
    no warning.

12. Programmatic wall promotion changes the value:
    no warning from this feature.

13. User changes Wall and the inventory read fails:
    keep the wall change; no blocker/modal.

14. Mixed Space still permits same-thickness connector use:
    do not globally disable Generate Connector.

15. Three-way orientation:
    no orientation setting. The canonical missing quadrant is rotated physically by the user.

16. Base Trim / B4B / lid:
    existing connector exclusions remain authoritative.
