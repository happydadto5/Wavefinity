**Implementation thread title:** `(12) Side Openings Imp`

## Goal

Add a bin-level **Side Openings** option for finger-access cutouts in selected bin walls. The motivating use case is a bin holding a stack of sticky-note pads: the bin remains a normal Wavefinity bin, but selected walls get centered finger slots so the stack can be gripped and lifted out.

This is a **Parts & options** feature, but it is not a placed interior part. It modifies the bin body itself, like Lid & Stacking. The current UI heading on `main` already says **Parts & options**; keep that wording.

The key architecture rule is exactly the one discussed: **build the normal bin first, then subtract negative cutter solids through the selected wall(s).** Do not rewrite, fork, approximate, or duplicate Wavefinity's normal outer-wall, cavity, floor, wave, stack, or connector geometry.

## User-facing behavior

Add a compact **Side Openings** bin-option card under the existing **Parts & options** heading, alongside the existing bin-level Lid & Stacking option and before the interior-part palette.

Default state is Off. When the user adds Side Openings, start with:

- **Shape:** Curved
- **Sides:** Front on; Back, Left, Right off
- **Opening size:** Medium — 10 mm
- **Depth:** 100%
- **Top Support:** Off

The controls are:

1. **Shape** — select with exactly:
   - Curved
   - Square

2. **Sides** — four independent compact checkbox/toggle controls:
   - Front
   - Back
   - Left
   - Right

   These are independent on/off choices, not a mutually exclusive segmented choice.

3. **Opening size** — named presets, matching the naming style already used elsewhere:
   - Small — 8 mm
   - Medium — 10 mm **(default)**
   - Large — 15 mm
   - XL — 20 mm

4. **Depth** — percentage input, 1–100, default **100**.
   Help text should make the meaning unambiguous:
   - 100% reaches the **top of the base/floor** but never cuts the base.
   - 50% reaches halfway down the usable wall height.

5. **Top Support** — checkbox, default Off.
   - Off = the opening is an open-top notch.
   - On = preserve a continuous bridge across the top of the wall.
   - Curved shape uses a smooth printable arch under the bridge.
   - Square shape uses a 45° roof/chamfer under the bridge so it prints without support.

Do not add free-form opening-width or bridge-thickness controls.

## Size availability

A wall can receive a Side Opening only when the wall is at least **2 Wavefinity units / 16 mm** long.

Wall span is determined by the direction the opening runs:

- Front / Back opening width runs along X, so those sides require `box.x >= 16 mm`.
- Left / Right opening width runs along Y, so those sides require `box.y >= 16 mm`.

If both axes are below 16 mm, the card remains visible but Add is disabled and it says:

> Side openings require at least one bin side to be 2 units (16 mm) or longer.

If one axis qualifies, only the corresponding side toggles are enabled.

Keep a **4 mm solid corner shoulder at each end** of an opening. Define this from the Wavefinity grid, not as unrelated magic:

`SIDE_OPENING_CORNER_MARGIN_MM = BASE_UNIT / 2`

Therefore a width preset is horizontally valid on a selected wall only when:

`opening_width_mm <= side_length_mm - 2 * SIDE_OPENING_CORNER_MARGIN_MM`

That intentionally gives these easy-to-understand modular outcomes:

- 2U / 16 mm wall → Small 8 mm only
- 3U / 24 mm wall → Small 8, Medium 10, Large 15
- 4U / 32 mm or larger wall → all four presets, including XL 20

The browser should only offer sizes valid for **all currently selected sides**. If selecting a newly checked side makes the current preset too large, automatically step down to the largest valid preset and visibly flash/update the size control. Never retain an impossible hidden value.

If a bin resize makes a selected side fall below 2U, turn that side off and show a short inline note explaining why; do not silently save an invalid configuration.

## Exact opening geometry

The cutter is always centered along the selected wall.

### Vertical depth

Let:

- `floor_z = box.base_thickness`
- `rim_z = box.z`
- `usable_wall_height = rim_z - floor_z`
- `depth_fraction = depth_percent / 100`
- `bottom_z = rim_z - usable_wall_height * depth_fraction`

`bottom_z` is the **deepest point** of the opening.

At 100%, `bottom_z == floor_z`. The cutter may meet the floor top exactly, but it must never extend below `floor_z` or remove base material.

### Curved, Top Support OFF

Use a classic open-top U-shaped finger slot:

- opening radius `r = opening_width / 2`
- lower boundary is a semicircle whose deepest point is `bottom_z`
- the semicircle rises to `bottom_z + r` at the left/right edges
- vertical sides continue from those endpoints through/past the rim so the notch is open at the top

Require enough vertical depth for the lower half-circle:
`rim_z - bottom_z >= r`.

### Square, Top Support OFF

Use a centered rectangular notch:

- flat bottom at `bottom_z`
- vertical sides at ± opening_width/2
- cutter continues through/past the rim

### Top Support ON

Preserve a fixed continuous top bridge. Do not invent another setting.

Use:

`SIDE_OPENING_TOP_BRIDGE_MM = LOCK_TOP_BELOW_RIM`

which is currently 4.0 mm and deliberately aligns the new feature with the existing upper-wall/lock geometry vocabulary.

Define:

`opening_top_z = rim_z - SIDE_OPENING_TOP_BRIDGE_MM`

For **Curved**, the upper boundary is a semicircular arch of radius `r`, with its apex at `opening_top_z`. The result is a rounded/capsule-like opening: U bottom plus arched top. Require:

`opening_top_z - bottom_z >= 2 * r`

For **Square**, keep the bottom flat and make the upper boundary a support-free 45° roof:

- apex centered at `opening_top_z`
- roof shoulders at ± opening_width/2 and `opening_top_z - opening_width/2`
- the two roof legs are exactly 45°

Require:

`opening_top_z - bottom_z >= opening_width / 2`

If the current Depth/Shape/Top-Support combination makes a width preset vertically impossible, do not offer that preset in the size selector. Python remains authoritative and must reject any impossible saved/imported combination with an actionable error.

Use the existing curve sampling conventions/helpers rather than creating a visibly faceted low-resolution arch.

## Negative-cutter implementation

Create a focused module, recommended name:

`organizer_side_openings.py`

It should own Side Opening validation and cutter generation so `organizer_engine.py` does not become a second copy of the geometry logic.

Recommended public helpers:

- `side_opening_side_span(box, side) -> float`
- `side_opening_allowed_sizes(box, spec) -> ...`
- `validate_side_openings(box) -> None`
- `side_opening_cutters(box) -> list[trimesh.Trimesh]`
- `apply_side_openings(box, mesh) -> trimesh.Trimesh`

Build one 2D run-vs-Z profile for each selected side and extrude it completely through the wall normal. Reuse `organizer_geometry._extrude_xz_profile`, `_extrude_yz_profile`, Shapely polygons, existing booleans, and existing Wavefinity constants. Do not reproduce the wavy wall surface.

The cutter normal span must fully cross the most-inward and most-outward possible wavy wall surface, with a small boolean epsilon outside each face. Derive that from the existing wall depth / `WAVE_AMPLITUDE`; do not assume a flat 0.8 mm wall.

Side mapping:

- Front = -Y wall, run axis X
- Back = +Y wall, run axis X
- Left = -X wall, run axis Y
- Right = +X wall, run axis Y

Apply the cutter as a **difference after the ordinary body/adders are built**. Side Openings must not change the base Wavefinity shell calculation.

Because later body-level operations can add material back across a wall, re-apply the Side Opening cutters to the completed bin body before export. The final printed body must always retain the requested opening even when fused features, scoop geometry, stack geometry, a rim ledge on another wall, etc. were built earlier.

After each final cut, clean unreferenced vertices and require the result to remain one printable solid. Fail clearly if a requested cut would split or destroy the body.

## Compatibility rules

Side Openings are for **ordinary bins only**.

- B4B: unavailable/hidden; reject imported B4B data that tries to enable them.
- Base Trim: unavailable/hidden.
- Lid & Stacking: allowed only with **Top Support ON**, because the continuous top rim must be preserved. In the browser, if Lid/Stacking is already active when Side Openings are added, automatically turn Top Support on and disable that checkbox with a short explanatory note. If Lid/Stacking is enabled later, do the same. Python must enforce this too.
- Rim label: a rim label may not occupy the same wall as a Side Opening. Reject with a clear message telling the user to move the rim label or deselect that side.
- Edge Mount: its active mounting side may not also have a Side Opening. Reject that overlap; different walls are allowed.
- Lift Grabbers: a Lift Grabber may not share a wall with a Side Opening because both are centered finger-access geometry. Different walls are allowed. Map `sides` / `front_back` / `both` to actual walls and reject only the overlap.
- Curved Scoop/interior parts: do not globally block them. The final negative cutter is authoritative wherever body geometry intersects the requested wall opening.

Do not make connector generation globally unavailable just because a bin has Side Openings. The user can use connectors on unaffected wall locations/sides. This fix should not invent connector-placement logic.

## Preview

Avoid drawing Lift Grabbers twice when the cut-body mesh already contains them.

For fused pieces that could intersect the cut, apply the same Side Opening cutter to their preview mesh where needed so preview and export agree. Do not create separate browser-side geometry math.

2D does not need a draggable placed-part footprint. If useful, a small non-interactive wall marker is okay, but it is not required for completion; the authoritative visible result is the 3D cut body.

### Key decisions

- **Geometry**: cutter cross-sections are built as plain Shapely polygons in local (tangent, Z) coordinates and extruded with the existing `_extrude_xz_profile`/`_extrude_yz_profile` helpers (Front/Back use the XZ extruder across world Y, Left/Right use the YZ extruder across world X) — no new extrusion machinery. Curved arcs sample 32 segments via `np.linspace`, matching the existing `SCOOP_CURVE_SEGMENTS` convention. The wall-normal span of each cutter overshoots the nominal outer/cavity surfaces by `WAVE_AMPLITUDE + 0.5 mm` each way so it fully crosses the real wavy wall regardless of wave phase, rather than assuming a flat wall thickness.
- **One shared cut point for export**: rather than baking Side Openings into `make_box()`, the cutter is applied once, at the very end of both the fused and box/insert generation paths, after every other body-level operation (fused features, scoop, rim ledge, Edge Mount, floor text). This satisfies "build the normal bin first, then subtract" without needing a separate "reapply" pass, since nothing runs after it.
- **Preview parity**: when Side Openings are enabled, preview builds the real cut shell via `make_box()` → (`apply_edge_mount_structure` if active) → `apply_side_openings()`, analogous to the existing Edge Mount preview path, instead of the lightweight synthesized-quad wall. Fused-mode scoop/rim-ledge/interior-feature preview meshes are also cut individually so preview and export agree.
- **Validation split**: `organizer_side_openings.validate_side_openings(box)` owns everything expressible from `BoxSpec` alone (per-wall length/width/vertical feasibility, Lift Grabber and Edge Mount wall conflicts, the Lid & Stacking → Top Support requirement). The rim-label conflict is checked separately in `organizer_app.validate_side_opening_label()` because the rim label's text/side are generation parameters, not `BoxSpec` fields.
- **B4B/Base Trim**: B4B is rejected in Python (`validate_b4b_side_openings`, called from `validate_b4b_design`), since a B4B `BoxSpec` still technically carries a `side_openings` field. Base Trim needs no Python-side rejection since `BaseTrimSpec` is an entirely separate, disjoint design schema with no such field at all — only the browser hides the card for it.
- **Bug found and fixed along the way**: the fused export path's no-inlays branch (`export_mesh(body, ...)`) was writing the stale pre-`apply_texts` `body` instead of the `reported` mesh whenever there was no rim label/floor text/Edge Mount label — a latent bug that would have made Side Openings' final cut (and any future post-`apply_texts` body operation) silently vanish from that export path. Fixed to export `reported` (identical to `body` when there is nothing to inlay, so no behavior change for existing designs).
