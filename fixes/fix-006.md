# Product contract

## 1. Permanent Space identity

A typed Wavefinity Space is identified by a permanent UUID stored in the folder's existing `.wavefinity.json`:

~~~json
{
  "version": 5,
  "setup_version": 1,
  "folder_mode": "space",
  "space_id": "2b9d7f6d-0000-4000-8000-000000000000",
  "inventory": true,
  "space": {
    "kind": "drawer",
    "name": "Bathroom Vanity",
    "x": 320,
    "y": 240,
    "z": 55
  },
  "keep_bin_defaults": true,
  "bin_defaults": null
}
~~~

The UUID is the identity. These are not identity:
- absolute path;
- folder basename;
- Space display name;
- inventory filename.

A Space keeps the same `space_id` through:
- Space-name edits;
- dimension edits;
- Keep Bin Defaults changes;
- folder renames;
- folder moves;
- inventory edits;
- metadata rewrites.

A **New Drawer Space** is a new physical Space and receives a brand-new UUID even when dimensions are prefilled from another drawer.

Untyped `folder_mode="design"` folders do not receive fake Space IDs.

Do not add another JSON identity file. `.wavefinity.json` remains the one folder metadata file.

Do not store `space_id` inside inventory `layout.space`. Identity belongs only in `.wavefinity.json`.

## 2. Local Space registry

Local desktop Wavefinity stores a durable registry in the user's profile preferences:

~~~json
{
  "space_registry": {
    "<space-id>": {
      "name": "Bathroom Vanity",
      "kind": "drawer",
      "folder": "C:\\Wavefinity\\Bathroom Vanity",
      "last_seen": "2026-09-19T01:30:00+00:00"
    }
  },
  "active_space_id": "<space-id>",
  "output": "C:\\Wavefinity\\Bathroom Vanity"
}
~~~

Rules:
- registry key = canonical `space_id`;
- registry name/kind are cached display data only;
- folder metadata wins whenever the folder is accessible;
- folder is the last known resolved absolute path;
- registry is **not** limited to eight entries;
- `MAX_RECENT` limits only the Welcome Recent list;
- inventory/layout never move into the registry;
- forgetting a Space removes the registry shortcut, not folder data;
- opening it again re-registers it.

## 3. Stable inventory filename

The current inventory filename becomes exactly:

`Wavefinity bins.md`

This applies to every inventory-enabled Wavefinity folder:
- typed Drawer;
- typed Surface;
- typed Portable;
- untyped Design folder with inventory enabled.

Folder rename must never change the inventory filename again.

## 4. Rename and move behavior

Same-parent rename:
- recover automatically from the registry by exact `space_id`;
- update registry path;
- update active `output` when relevant;
- continue normal startup/open.

Move elsewhere:
- do not scan the whole drive;
- manual Open Existing Space reads the same `space_id`;
- if the old registered location is missing/stale, adopt the new path.

Copied Space:
- if old registered path still exists and both folders contain the same UUID, this is a duplicate identity;
- do not silently choose one;
- do not silently mint a new ID;
- reject/open a clear duplicate-identity error.

## Replace path-only behavior with one resolver

The current `inventory_path()` blindly constructs:

~~~python
output_dir / f"{output_dir.name} bins.md"
~~~

Replace the runtime path decision with one authoritative resolver.

Use behavior equivalent to:

~~~python
class InventoryMigrationError(ValueError):
    pass


def resolve_inventory_path(output_dir: Path | str, *, migrate: bool) -> Path:
    folder = Path(output_dir).expanduser().resolve()
    canonical = folder / INVENTORY_FILENAME

    legacy = []
    preferred = folder / f"{folder.name} bins.md"
    if preferred.is_file():
        legacy.append(preferred)

    if folder.is_dir():
        for candidate in folder.glob("* bins.md"):
            if (
                candidate.is_file()
                and candidate.name != INVENTORY_FILENAME
                and candidate not in legacy
            ):
                legacy.append(candidate)

    if canonical.is_file():
        if legacy:
            differing = [
                candidate for candidate in legacy
                if candidate.read_bytes() != canonical.read_bytes()
            ]
            if differing:
                raise InventoryMigrationError(
                    "Multiple Wavefinity inventory files were found; nothing was changed."
                )
            if migrate:
                for candidate in legacy:
                    candidate.unlink()
        return canonical

    if not legacy:
        return canonical

    if len(legacy) != 1:
        raise InventoryMigrationError(
            "Multiple Wavefinity inventory files were found; nothing was changed."
        )

    source = legacy[0]
    if not migrate:
        return source

    source.replace(canonical)
    return canonical
~~~

Important:
- run this under `INVENTORY_LOCK`;
- read-only load may read a legacy file without renaming it;
- a write/open migration may rename it;
- canonical + different legacy = hard stop;
- canonical + identical legacy = on migrate/write, remove the redundant legacy **before the canonical file changes**, otherwise the next write would falsely become a conflict;
- do not merge two inventories;
- do not create a blank canonical inventory as recovery;
- do not touch `*.bak` history files.

Keep `inventory_path()` only if compatibility callers/tests require it. If kept, make it mean the canonical path only:

~~~python
def inventory_path(output_dir):
    return Path(output_dir).expanduser().resolve() / INVENTORY_FILENAME
~~~

Runtime reads/writes must use `resolve_inventory_path()`, not `inventory_path()` directly.

# Correction 2 — Durable Forget + final generated-ID duplicate guard

Review target: `3ff62ce6e9535f5b9379356ea83f2e5d79009a32`.

Do not redesign the registry, startup flow, or identity model.

## A. Forgetting the current typed Space must survive restart

Current behavior:

1. a typed Space is active;
2. `/api/space/forget` removes its registry entry and clears `active_space_id`;
3. per the original plan, `output` is intentionally allowed to remain so the currently-open app can still use/show the folder;
4. on the next launch, `/api/space/startup` sees no `active_space_id` and falls back to `prefs["output"]`;
5. it opens the same v5 typed Space and `remember_prepared()` immediately re-registers it.

That makes Forget non-durable: the forgotten Space comes back automatically without the user explicitly opening it again.

The product contract says forgetting removes the registry shortcut and **opening it again** re-registers it. An automatic restart fallback is not an explicit reopen.

### Exact repair — `organizer_spaces.py`

Keep the existing rule that Forget may leave `output` untouched so the current session and Show Folder behavior remain intact.

Change `startup()` so the legacy `output` fallback does **not** automatically reopen a current v5 typed Space that has been forgotten.

Required logic:

- If a valid `active_space_id` exists, keep the current ID-first startup behavior exactly.
- If there is no active ID and `prefs["output"]` exists:
  1. resolve the output path if it exists;
  2. classify it read-only;
  3. if it is a typed **v5** Space with a valid `space_id`;
  4. and that ID is **not present** in `space_registry`;
  5. treat it as intentionally forgotten for startup purposes:
     - do not call `prepare_folder_for_open()`;
     - do not call `remember_prepared()`;
     - return Home/Recents with `folder: None`.

Preserve fallback compatibility for:
- v2/v3/v4 typed folders that still need migration/identity registration;
- untyped Design folders;
- current v5 typed folders whose ID is still present in the registry but `active_space_id` is absent for some benign reason.

Do not clear `output` merely to solve this. It may remain the trusted current folder for the live session.

A small helper is acceptable, for example:

```python
def _output_is_forgotten_typed_space(target: Path, prefs: dict[str, Any]) -> bool:
    info = describe(target, prefs)
    if info["folder_mode"] != "space" or not info["space_id"]:
        return False
    if _metadata_version(target) != METADATA_VERSION:
        return False
    return info["space_id"] not in _space_registry(prefs)
```

Use equivalent logic if a different local structure is cleaner.

## B. Implement the plan’s final duplicate guard after a newly-generated ID

The final Fix 006 plan explicitly required:

1. classify read-only;
2. if an ID already exists, duplicate-check before mutation;
3. migrate inventory;
4. write v5/ID;
5. re-read;
6. **if the ID was newly generated, run a final duplicate guard**;
7. only then update registry/output/last_seen.

Current `prepare_folder_for_open()` performs the pre-mutation duplicate guard when an ID already exists, but after a v4 typed Space without an ID is upgraded and receives a new UUID, it only re-reads and checks that an ID exists. It never calls the duplicate guard for that newly-created identity.

A random UUID collision is extraordinarily unlikely, but this was an explicit safety requirement and the completion review must verify the whole plan, not only likely paths.

### Exact repair — `organizer_spaces.py`

In `prepare_folder_for_open()`:

- remember whether the typed folder already had an ID before mutation;
- keep the existing pre-mutation guard for an existing ID;
- after v4 -> v5 rewrite and re-read:
  - require the resulting ID as today;
  - if the folder was typed and **did not have an ID before the rewrite**, call:
    `_check_not_duplicate(info["space_id"], target, prefs)`
    before returning;
- registry/profile mutation remains later in `remember_prepared()`.

Equivalent structure:

```python
typed = info["folder_mode"] == "space"
had_space_id = bool(info.get("space_id"))

if typed and had_space_id:
    _check_not_duplicate(info["space_id"], target, prefs)

...

info = describe(target, prefs)

if typed:
    if not info["space_id"]:
        raise FolderMetadataError(...)
    if not had_space_id:
        _check_not_duplicate(info["space_id"], target, prefs)

return info
```

Do not remove the existing pre-mutation guard.
