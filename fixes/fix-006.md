# Product contract

## 1. Permanent Space identity

A typed Wavefinity Space is identified by a permanent UUID stored in the folder's existing `.wavefinity.json`:

~~~json
{
  "version": 5,
  "setup_version": 1,
  "folder_mode": "space",
  "space_id": "2b9d7f6d-0000-4000-8000-000000000000",
  "inventory": true,
  "space": {
    "kind": "drawer",
    "name": "Bathroom Vanity",
    "x": 320,
    "y": 240,
    "z": 55
  },
  "keep_bin_defaults": true,
  "bin_defaults": null
}
~~~

The UUID is the identity. These are not identity:
- absolute path;
- folder basename;
- Space display name;
- inventory filename.

A Space keeps the same `space_id` through:
- Space-name edits;
- dimension edits;
- Keep Bin Defaults changes;
- folder renames;
- folder moves;
- inventory edits;
- metadata rewrites.

A **New Drawer Space** is a new physical Space and receives a brand-new UUID even when dimensions are prefilled from another drawer.

Untyped `folder_mode="design"` folders do not receive fake Space IDs.

Do not add another JSON identity file. `.wavefinity.json` remains the one folder metadata file.

Do not store `space_id` inside inventory `layout.space`. Identity belongs only in `.wavefinity.json`.

## 2. Local Space registry

Local desktop Wavefinity stores a durable registry in the user's profile preferences:

~~~json
{
  "space_registry": {
    "<space-id>": {
      "name": "Bathroom Vanity",
      "kind": "drawer",
      "folder": "C:\\Wavefinity\\Bathroom Vanity",
      "last_seen": "2026-09-19T01:30:00+00:00"
    }
  },
  "active_space_id": "<space-id>",
  "output": "C:\\Wavefinity\\Bathroom Vanity"
}
~~~

Rules:
- registry key = canonical `space_id`;
- registry name/kind are cached display data only;
- folder metadata wins whenever the folder is accessible;
- folder is the last known resolved absolute path;
- registry is **not** limited to eight entries;
- `MAX_RECENT` limits only the Welcome Recent list;
- inventory/layout never move into the registry;
- forgetting a Space removes the registry shortcut, not folder data;
- opening it again re-registers it.

## 3. Stable inventory filename

The current inventory filename becomes exactly:

`Wavefinity bins.md`

This applies to every inventory-enabled Wavefinity folder:
- typed Drawer;
- typed Surface;
- typed Portable;
- untyped Design folder with inventory enabled.

Folder rename must never change the inventory filename again.

## 4. Rename and move behavior

Same-parent rename:
- recover automatically from the registry by exact `space_id`;
- update registry path;
- update active `output` when relevant;
- continue normal startup/open.

Move elsewhere:
- do not scan the whole drive;
- manual Open Existing Space reads the same `space_id`;
- if the old registered location is missing/stale, adopt the new path.

Copied Space:
- if old registered path still exists and both folders contain the same UUID, this is a duplicate identity;
- do not silently choose one;
- do not silently mint a new ID;
- reject/open a clear duplicate-identity error.

## Replace path-only behavior with one resolver

The current `inventory_path()` blindly constructs:

~~~python

~~~

Replace the runtime path decision with one authoritative resolver.

Use behavior equivalent to:

~~~python
class InventoryMigrationError(ValueError):
    pass


def resolve_inventory_path(output_dir: Path | str, *, migrate: bool) -> Path:
    folder = Path(output_dir).expanduser().resolve()
    canonical = folder / INVENTORY_FILENAME

    legacy = []
    preferred = folder / f"{folder.name} bins.md"
    if preferred.is_file():
        legacy.append(preferred)

    if folder.is_dir():
        for candidate in folder.glob("* bins.md"):
            if (
                candidate.is_file()
                and candidate.name != INVENTORY_FILENAME
                and candidate not in legacy
            ):
                legacy.append(candidate)

    if canonical.is_file():
        if legacy:
            differing = [
                candidate for candidate in legacy
                if candidate.read_bytes() != canonical.read_bytes()
            ]
            if differing:
                raise InventoryMigrationError(
                    "Multiple Wavefinity inventory files were found; nothing was changed."
                )
            if migrate:
                for candidate in legacy:
                    candidate.unlink()
        return canonical

    if not legacy:
        return canonical

    if len(legacy) != 1:
        raise InventoryMigrationError(
            "Multiple Wavefinity inventory files were found; nothing was changed."
        )

    source = legacy[0]
    if not migrate:
        return source

    source.replace(canonical)
    return canonical
~~~

Important:
- run this under `INVENTORY_LOCK`;
- read-only load may read a legacy file without renaming it;
- a write/open migration may rename it;
- canonical + different legacy = hard stop;
- canonical + identical legacy = on migrate/write, remove the redundant legacy **before the canonical file changes**, otherwise the next write would falsely become a conflict;
- do not merge two inventories;
- do not create a blank canonical inventory as recovery;
- do not touch `*.bak` history files.

Keep `inventory_path()` only if compatibility callers/tests require it. If kept, make it mean the canonical path only:

~~~python
def inventory_path(output_dir):
    return Path(output_dir).expanduser().resolve() / INVENTORY_FILENAME
~~~

Runtime reads/writes must use `resolve_inventory_path()`, not `inventory_path()` directly.

# Class C risk-directed testing — exact gate

## Risks these checks must catch

1. v4 configured Space accidentally re-enters onboarding after version bump.
2. metadata rewrite loses/replaces the UUID.
3. rename recovery points at the wrong folder or duplicate copies silently merge.
4. inventory migration creates a blank/split inventory or loses rows/layout.
5. preference migration writes to the wrong location or loses existing settings.
6. local startup/Recents/Forget route contracts break at runtime.
7. hosted browser code drops the ID or uses the wrong selected directory.
8. JavaScript/Python integration has a syntax/import/runtime wiring error.

## A. Add one focused regression test module

Prefer a new:

### test_v4_typed_open_upgrades_to_v5_without_setup
