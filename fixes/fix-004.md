# Goal

Replace the current folder-first / optional-Space-planning experience with a first-run and new-Space flow built around what the person is physically organizing.

The normal new-user flow is:

1. Welcome screen.
2. **Create New Space**.
3. Choose one of three visual Space types:

- **Configure this folder as a Wavefinity Space**
- **Use this folder without a Space type**

Existing Wavefinity folders must go through the new setup once after this schema change. Preserve their inventory/design/layout data.

# New metadata / migration model

Current code treats Space as optional and only knows `drawer` / `box`. Replace that with an explicit onboarding-aware schema.

## Metadata version

Bump `.wavefinity.json` from version 3 to **version 4**.

Add a constant such as:

```python

SPACE_SETUP_VERSION = 1
```

Newly configured folders write:

```json
{
  "version": 4,
  "setup_version": 1,
  "folder_mode": "space",
  "inventory": true,
  "space": { ... },
  "keep_bin_defaults": true,

```

- `surface`
- `portable`

Read legacy `box` safely for migration, but do not write `box` for a newly configured Space. Legacy `box` preselects **Portable Storage** in the migration wizard.

- prefill its existing dimensions/name.

Preserve:

Do not clear inventory or replace the inventory file just to migrate metadata.

# Spacer redesign

This is a real redesign of Drawer spacer planning. Do not preserve the old “fill every empty grid cell plus tiny edge shim” behavior as the normal user path.

The human requirement is:

- spacers conform to the **actual physical gap**, not 8 mm units;
- only suggest spacers going toward the **back** or **right** wall;
- smaller strategically placed spacer pieces are preferred over giant fillers;
- suggest the best **2–4** by default, using a formula;
- if 2 or 3 small spacers are enough to restrain the whole connected layout, stop there;
- show additional obvious candidate gap areas visually so the user can add more;
- allow selected spacers to be removed before generation;
- flexible spacer is ON by default;
- flexible spacer should provide roughly 1–3 mm of compliant travel;
- nominal physical gap remains `drawer dimension - bin/component edge`;
- flexible printed length should add about **0.5 mm preload** beyond the measured gap;
- rigid mode uses the exact measured gap;
- no thin wall-edge shim concept.

## Planner must be separate from generation

Current `DL.makeSpacers()` calls `/api/drawer/spacers` and immediately writes/generated/places parts. That is no longer acceptable.

Split into:

1. **Plan spacers** — pure/read-only.
2. Show candidates and selected defaults in the drawer preview.
3. User toggles candidates.
4. **Generate selected spacers** — writes files/inventory/placements.

Suggested routes:
- `/api/drawer/spacer-plan`
- existing `/api/drawer/spacers` becomes generation of explicitly selected candidate IDs

The server must recompute/validate candidate IDs against the current layout before generating. Do not trust arbitrary client x/y/w/d geometry.

## Candidate construction

Use only non-spacer placed bins/stacks.

Treat each stack footprint once.

Build connected components from bin footprints that physically touch along a useful shared edge. Reuse the same adjacency/seam concepts already used by connector reporting where practical. The purpose is to recognize an L-shaped or rectangular group of bins that moves as one practical cluster; do not require one spacer behind every bin in a connected cluster.

For each connected component:

### Back candidates
Find exposed back-facing runs. For a useful run, compute:

```
gap = drawer usable back wall position - component exposed back edge
```

Candidate runs from the component's back face toward the back wall.

### Right candidates
Find exposed right-facing runs. Compute:

```
gap = drawer usable right wall position - component exposed right edge
```

Candidate runs from the component's right face toward the right wall.

Do not create front or left candidates.

Avoid:
- overlaps with bins;
- keep-out zones;
- impossible tiny geometry;
- duplicate candidates that restrain the same component/axis at essentially the same location.

The contact width along the bin face should be deliberately compact. Prefer a short stable pad/run rather than spanning the entire exposed side. A target around 24–32 mm is reasonable, clipped to the available exposed run and manufacturable minimum. Reuse current wall/wave geometry helpers rather than inventing a second Wavefinity mating profile.

The spacer's long dimension is the exact real gap; it is **not** rounded to `BASE_UNIT`.

## Choosing the default best 2–4

Do not simply choose the four largest empty rectangles.

Rank candidates for **restraining benefit per printed size**.

A deterministic greedy set-cover style selection is appropriate:

1. Each connected component has potential restraint needs in +X (right) and +Y (back), except an axis already effectively against its wall.
2. A candidate covers one component/axis restraint need.
3. Weight the benefit by the component's footprint area / number of bins so restraining a large connected group is valuable.
4. Penalize long/bulky spacers. Prefer shorter/smaller candidates when two choices provide comparable restraint.
5. Greedily choose the candidate with the best new-restraint benefit / material-footprint cost.
6. Stop when all practical component restraint needs are covered or four candidates have been selected.
7. If coverage is already achieved with 2 or 3, stop there.
8. If only one valid candidate exists, one is acceptable. Otherwise the normal target range is 2–4.
9. Keep additional valid candidates as **unselected** options for the visual preview.

Use a stable tie-breaker based on side + coordinates so the same layout gives the same suggestions.

## Flexible spacer geometry

Add a setting under spacer controls:

**Flexible fit** — default ON.

When ON:
- measured gap remains the real drawer-to-bin distance;
- target overall printed spacer length is approximately `gap + 0.5 mm`;
- incorporate a center flexure that allows about **1–3 mm axial compression** without making the wall-contact or bin-contact pads floppy;
- print flat with no required supports.

The preferred implementation is a full-height planar serpentine/S flexure between two rigid end pads:
- rigid Wavefinity-mating pad at the bin end;
- rigid flat pad at the drawer-wall end;
- one or more S/serpentine webs around ~1.5 mm thick in plan, sized/limited by the available spacer length;
- slots/openings run through Z, so there is no horizontal bridge/roof needing support;
- the spring is compliant along the spacer's long axis, not a thin unsupported plate.

Do not promise mathematically exact spring force. The design target is practical 1–3 mm give for normal printed plastic.

For a gap too short to contain a safe flexure:
- generate a rigid exact-gap spacer;
- surface a note that the spacer is too short for the flexible section;
- do not create fragile geometry merely to satisfy the toggle.

When Flexible fit is OFF:
- use the exact measured gap;
- use rigid geometry.

Reuse existing phase-correct wavy outline/profile helpers for the bin-facing end. The wall-facing end is flat.

## Spacer height

Keep the existing spacer-height concept unless current code has a stronger authoritative rule. Default may remain 15 mm and may not exceed usable drawer height.

Do not tie X/Y spacer size to 8 mm units.

## Preview interaction

Add spacer-planning state in `web/drawer-model.js`, separate from saved layout, e.g.:

## J. Finish the strategic spacer geometry that Fix 004 specified

The current planner still creates each right/back candidate across the full min-to-max exposed component run:

```python
d = (max_y - min_y) * step
w = (max_x_comp - min_x) * step
```

That can produce very large wall strips and can bridge holes/non-contiguous exposed edges.

Fix 004 asked for small strategic contact pieces, normally about 24–32 mm of contact width, not giant strips.

For each connected component/side:
- derive actual contiguous exposed boundary segments;
- choose a deterministic useful segment;
- target about 28 mm contact width, clipped to the available exposed segment (use the full segment if it is shorter);
- do not bridge a gap between separate exposed runs;
- reject a candidate whose physical path intersects another bin/component or a keepout;
- keep the spacer's long axis equal to the real measured component-to-wall gap;
- keep only back/right candidates.

Candidate IDs must remain deterministic from the authoritative geometry.

### Honor or remove `max_length`

If the setting remains visible, implement the printability splitting behavior described by Fix 004. If no safe split is implemented, remove the dead control/setting rather than pretending it affects output.

## K. Prevent spacer file collisions and record the real printed size

Current filename:

```python

```

truncates real unsnapped gap dimensions.

Examples such as 12.1 mm and 12.9 mm can map to the same filename and overwrite each other. Flexible and rigid variants can also receive the same filename.

Use a deterministic filename that includes:
- Flexible vs Rigid;
- side;
- sufficient decimal precision for the real geometry (or a stable short geometry hash);
- height.

Do not truncate unsnapped physical dimensions to integers.

For Flexible spacers, the mesh's long-axis physical target is approximately measured gap + 0.5 mm. Keep these concepts distinct:
- placement envelope/gap = measured drawer gap;
- printed physical part size = actual generated mesh target including preload.

Inventory X/Y should describe the actual printed part, while the free placement `x/y/w/d` continues to describe where the measured gap lies in the drawer.
